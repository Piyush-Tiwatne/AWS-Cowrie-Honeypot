# Cowrie Log Analysis

## 1. Overview

Cowrie stores honeypot activity in structured JSON log files.

Python was used to process these logs and extract information related to:

- SSH connection sessions
- Source IP addresses
- Authentication activity
- SSH client information
- Commands entered
- HASSH fingerprints
- Session activity patterns

The analysis was performed using the Cowrie logs collected during the project data-collection period.

---

## 2. Cowrie Log Location

The Cowrie logs were stored on the Ubuntu EC2 server at:

```text
~/cowrie/var/log/cowrie/
```

The JSON log files followed the naming pattern:

```text
cowrie.json
cowrie.json.<date>
```

These files contain structured event records generated by Cowrie during SSH sessions.

---

## 3. Python Analysis Script

The log analysis was performed using:

```text
scripts/analyze_cowrie.py
```

The script reads the available Cowrie JSON log files and processes individual events based on their event types.

The extracted information is aggregated into statistics covering:

- Connection activity
- Source IP addresses
- Usernames
- Commands
- SSH client strings
- HASSH fingerprints
- Activity by date

The script also excludes known project-owner test IP addresses so that manual testing does not significantly affect the external activity analysis.

---

## 4. Connection Analysis

SSH connection events were identified using:

```text
cowrie.session.connect
```

The analysis counted:

- Total SSH connection sessions
- Source IP addresses
- Connections by date

Only `cowrie.session.connect` events were counted when calculating the total number of SSH connection sessions.

This provided a consistent basis for measuring incoming SSH sessions recorded by the honeypot.

Three known project-owner test IP addresses were excluded when calculating external-source activity.

---

## 5. Authentication Analysis

Authentication activity was identified using the following Cowrie events:

```text
cowrie.login.success
cowrie.login.failed
```

The analysis recorded the usernames associated with successful authentication events.

Raw passwords collected during honeypot operation were not included in the public repository.

> **Important:** A `cowrie.login.success` event represents authentication accepted by Cowrie's emulated environment. It does not demonstrate successful compromise of the underlying EC2 host.

---

## 6. SSH Client Analysis

Cowrie records information about the SSH client presented by connecting systems.

The following event was used to analyze SSH client information:

```text
cowrie.client.version
```

The analysis identified recurring client and protocol strings in the collected data.

Examples observed in the dataset included:

- `SSH-2.0-Go`
- `SSH-2.0-paramiko_3.4.1`
- `SSH-2.0-libssh_0.7.4`
- `SSH-2.0-russh_0.51.1`
- `SSH-2.0-perlssh`

The `SSH-2.0-Go` client string was the most frequently observed client identifier in the collected dataset.

Client strings describe information presented by the connecting system and do not independently identify a specific attacker.

---

## 7. Command Analysis

Commands entered into the Cowrie emulated shell were identified using:

```text
cowrie.command.input
```

The analysis recorded command strings and counted their occurrences.

The most frequently observed command was:

```text
echo -e "\x6F\x6B"
```

This command appeared repeatedly across the collected sessions.

Another observed command pattern was:

```text
/bin/./uname -s -v -n -r -m
```

The `uname` command is commonly used to obtain operating-system and kernel information.

A further observed command was:

```text
echo 1 > /dev/null && cat /bin/echo
```

Highly repetitive command patterns were observed across the dataset.

The frequency and repetition of these commands indicate automated or scripted activity, although command patterns alone are not sufficient to identify a specific tool, malware family, or attacker.

---

## 8. HASSH Analysis

Cowrie records SSH handshake information that can include a HASSH fingerprint.

HASSH fingerprints were used to group connections according to their SSH handshake characteristics.

The analysis examined HASSH information associated with the collected SSH sessions and counted recurring fingerprints.

The dominant HASSH fingerprint observed in the dataset was:

```text
01ca35584ad5a1b66cf6a9846b5b2821
```

It appeared in a large number of connections, indicating a highly repetitive SSH handshake pattern.

> **Important:** A HASSH fingerprint is a grouping and fingerprinting mechanism. It does not identify a specific attacker by itself.

## 10. Observed Activity Patterns

The analysis showed repeated activity across several categories.

Observed patterns included:

- Repeated SSH connections
- Repeated authentication attempts
- Recurring SSH client information
- Repeated command sequences
- Recurring HASSH fingerprints
- Concentrated activity from individual source IP addresses

One source IP generated a very large number of repeated connections during the collection period.

The most frequent command was also highly repetitive, appearing thousands of times across the collected sessions.

These patterns indicate that a significant portion of the observed activity was automated or scripted.

However, the analysis does not attempt to identify a specific attacker, malware family, or tool based solely on these observations.

---

## 11. Important Interpretation

The results must be interpreted within the context of a honeypot environment.

### Authentication

A:

```text
cowrie.login.success
```

event indicates that authentication was accepted by Cowrie's emulated environment.

It should **not** be interpreted as successful compromise of the underlying AWS EC2 host.

### Source IP Addresses

A source IP address identifies a network endpoint involved in a connection.

It does not necessarily represent an individual attacker.

An address may belong to infrastructure such as:

- Cloud servers
- Proxies
- VPN services
- Potentially compromised systems
- Other network infrastructure

### SSH Client Information

Client strings describe information presented during the SSH connection.

They can help identify recurring connection characteristics, but they should not be treated as proof of attacker identity.

### HASSH Fingerprints

HASSH fingerprints can be useful for grouping connections with similar SSH handshake characteristics.

However, identical fingerprints do not prove that all connections originated from the same attacker or infrastructure.

## 14. Limitations

The analysis has several limitations:

1. **Limited dataset**

   The dataset represents activity collected by one honeypot deployment during a specific collection period.

2. **Not representative of all Internet SSH activity**

   The results should not be treated as representative of global or general Internet-wide SSH activity.

3. **IP address attribution**

   An IP address does not necessarily represent an individual attacker.

4. **GeoIP accuracy**

   GeoIP locations are approximate and should not be interpreted as the physical location of an attacker.

5. **Emulated environment**

   Cowrie provides an emulated SSH environment rather than a production SSH server.

6. **Authentication interpretation**

   Honeypot authentication events represent activity within the emulated environment and do not demonstrate compromise of the underlying EC2 host.

7. **Behavioral attribution**

   Observed connection, command, client, and HASSH patterns alone are insufficient to conclusively identify a specific attacker, malware family, or tool.

8. **Client identification**

   Client strings are based on information presented by connecting systems and may not reliably represent the actual software used by the remote system.

## 15. Result

The Python-based analysis successfully transformed the collected Cowrie JSON logs into structured information about:

- SSH sessions
- Authentication activity
- Source addresses
- Usernames
- SSH client information
- Commands
- HASSH fingerprints
- Activity over time

The final analysis recorded **28,905 SSH connection sessions**. After excluding three known project-owner test IP addresses, **28,902 external connection events** remained across **47 unique external source IP addresses**.

The analysis demonstrated how honeypot logs can be programmatically processed to identify recurring SSH activity patterns and support security monitoring and investigation.

The detailed results are documented separately in the [analysis results](../analysis/results.md).
