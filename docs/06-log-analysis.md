# Cowrie Log Analysis

## 1. Overview

Cowrie stores honeypot activity in structured JSON log files.

Python was used to process these logs and extract information related to:

* SSH connection sessions
* Source IP addresses
* Authentication activity
* SSH client information
* Commands entered
* HASSH fingerprints
* Session activity patterns

The analysis was performed using the collected Cowrie logs from the project data-collection period.

---

## 2. Cowrie Log Location

The collected Cowrie logs were stored on the Ubuntu EC2 server at:

```text id="p2x8vh"
~/cowrie/var/log/cowrie/
```

The main JSON log files followed the naming pattern:

```text id="q8h5rm"
cowrie.json
cowrie.json.<date>
```

These files contain structured event records generated by Cowrie during SSH sessions.

---

## 3. Python Analysis Script

The log analysis was performed using the following Python script:

```text id="7a4f1k"
scripts/analyze_cowrie.py
```

The script reads the available Cowrie JSON log files and processes individual events based on their event types.

The extracted information was then used to calculate activity statistics and identify recurring patterns.

---

## 4. Connection Analysis

SSH connection events were identified using:

```text id="x1s9dk"
cowrie.session.connect
```

The analysis counted:

* Total SSH connection sessions
* Source IP addresses
* Connections by date

Only `cowrie.session.connect` events were counted when calculating the total number of SSH connection sessions.

This provided a consistent basis for measuring the number of incoming SSH sessions recorded by the honeypot.

---

## 5. Authentication Analysis

Authentication activity was identified using the following Cowrie events:

```text id="5d7rqa"
cowrie.login.success
cowrie.login.failed
```

The analysis recorded the usernames associated with authentication events.

Raw passwords collected during honeypot operation were not included in the public repository.

> **Important:** A `cowrie.login.success` event represents authentication accepted by Cowrie's emulated environment. It does not demonstrate successful compromise of the underlying EC2 host.

---

## 6. SSH Client Analysis

Cowrie records information about the SSH client presented by connecting systems.

The following event was used to analyze SSH client information:

```text id="3w9n2e"
cowrie.client.version
```

The analysis identified recurring SSH client implementations in the collected data.

Examples observed in the dataset included:

* Go-based SSH clients
* Paramiko-based SSH clients

Recurring client information was used to identify connection patterns across the collected sessions.

---

## 7. Command Analysis

Commands entered into the Cowrie emulated shell were identified using:

```text id="c6k1vp"
cowrie.command.input
```

Examples observed during the collection period included:

```text id="e8n4rz"
uname
whoami
pwd
ls
```

Highly repetitive command patterns were also observed across multiple sessions.

For example, `uname` can provide information about the operating system and kernel details exposed by the emulated environment.

Command analysis helped identify the types of basic system and environment-discovery activity performed during SSH sessions.

---

## 8. HASSH Analysis

Cowrie records SSH handshake information that can include a **HASSH fingerprint**.

The following event was used to analyze recurring SSH handshake characteristics:

```text id="u5m3jx"
cowrie.client.kex
```

HASSH fingerprints can be used to group SSH connections that exhibit similar handshake characteristics.

This can help identify recurring client or connection patterns within the dataset.

> **Important:** A HASSH fingerprint does not identify a specific attacker by itself. It is a fingerprinting and grouping mechanism rather than an identity mechanism.

---

## 9. Analysis Results

During the project data-collection period, the analysis produced the following results:

| Metric                     | Result |
| -------------------------- | -----: |
| SSH connection sessions    | 28,897 |
| Unique external source IPs |     43 |
| Successful-login events    | 28,830 |
| Failed-login events        |      1 |

The **43 external source IPs** were calculated after excluding the project's own test traffic.

The **28,897 total connection sessions** include the project's own test session.

## 10. Observed Activity Patterns

The analysis showed a high level of repetition across several categories of activity.

Observed patterns included:

* Repeated SSH connections
* Repeated authentication events
* Recurring SSH client information
* Repeated command sequences
* Recurring SSH handshake characteristics

The frequency and repetition of these events suggest that a significant portion of the observed activity was automated or scripted.

However, the analysis does not attempt to identify a specific attacker, malware family, or tool based solely on these observations.

---

## 11. Important Interpretation

The results must be interpreted within the context of a honeypot environment.

### Authentication

A:

```text id="p7x2cs"
cowrie.login.success
```

event indicates that authentication was accepted by Cowrie's emulated environment.

It should **not** be interpreted as successful compromise of the underlying AWS EC2 host.

### Source IP Addresses

A source IP address identifies a network endpoint involved in the connection.

It does not necessarily represent an individual attacker.

An address may belong to infrastructure such as a cloud server, proxy, VPN, or potentially compromised system.

## 14. Limitations

The analysis has several limitations:

1. **Limited dataset**
   The dataset represents activity collected by one honeypot deployment during a specific collection period.

2. **Not representative of all Internet SSH activity**
   The results should not be treated as representative of global or general Internet-wide SSH activity.

3. **IP address attribution**
   An IP address does not necessarily represent an individual attacker.

4. **GeoIP accuracy**
   GeoIP locations are approximate and should not be interpreted as the physical location of an attacker.

5. **Emulated environment**
   Cowrie provides an emulated SSH environment rather than a production SSH server.

6. **Authentication interpretation**
   Honeypot authentication events represent activity within the emulated environment and do not demonstrate compromise of the underlying EC2 host.

7. **Behavioral attribution**
   The observed connection, command, and client patterns alone are insufficient to conclusively identify a specific attacker, malware family, or tool.

---

## 15. Result

The Python-based analysis successfully transformed the collected Cowrie JSON logs into structured information about SSH sessions, authentication activity, source addresses, SSH clients, commands, and HASSH fingerprints.

The analysis recorded **28,897 SSH connection sessions from 43 unique external source IP addresses**, after separating the project's own test traffic from external-source analysis.

The results demonstrated how honeypot logs can be programmatically processed to identify recurring SSH activity patterns and support security monitoring and analysis.
